# Model

## Goal

The model should support an explainable document-matching workflow for EU funding recommendations.
The target is a simple and defensible ML pipeline that can be trained in a notebook and then used by the backend.

## Training Artifact Target

The intended workflow is:

1. `model.ipynb` is executed;
2. the notebook preprocesses the data and trains the model artifacts;
3. the notebook saves the artifacts into the project file structure;
4. the backend loads those saved artifacts at runtime.

## Data Folder Structure

```text
data/
  raw/
    calls/
    briefs/
  processed/
  audit/
```

- `data/raw/calls/` stores the original funding call data and source documents;
- `data/raw/briefs/` stores sample municipal briefs;
- `data/processed/` stores cleaned datasets and model-ready artifacts;
- `data/audit/` stores traceability records generated by the application.

## Data Strategy

The dataset should be curated and small.

- `English-only` funding calls;
- `3-4` municipality-relevant categories;
- `40-60` calls total;
- `8-12` sample municipal briefs;
- official EU sources only.

## Recommended Categories

- smart cities / digital transition
- sustainability / energy efficiency
- mobility / infrastructure
- social inclusion / education

## Funding Call Data

Each funding call should include:

- `call_id`
- `title`
- `category`
- `program`
- `short_description`
- `full_text`
- `eligibility`
- `deadline`
- `geographic_scope`
- `source_url`
- `source_document`

## Sample Brief Data

Each sample municipal brief should include:

- `brief_id`
- `title`
- `municipality_profile`
- `project_need`
- `project_description`
- `expected_impact`
- `category`
- `ground_truth_calls` if known

## Recommended Baseline Model

The recommended v1 approach is:

- text preprocessing;
- `TF-IDF` vectorization;
- `cosine similarity` ranking.

This is appropriate because it is:

- easy to train;
- easy to explain;
- low risk;
- strong enough for a document-matching POC.

## Explainability Outputs

For each recommendation, the model pipeline should support:

- similarity score;
- top overlapping keywords;
- matched sentence or passage;
- short summary template.

The explanation should remain deterministic and easy to inspect.

## Notebook Responsibility

`model.ipynb` should handle:

- loading raw funding calls;
- loading sample briefs;
- cleaning and normalizing text;
- fitting the vectorizer;
- generating the document matrix;
- evaluating ranking quality on sample briefs;
- saving model artifacts for backend usage.

## Saved Artifacts

At minimum, the notebook should save:

- fitted vectorizer;
- funding call matrix;
- processed funding call dataset;
- metadata needed by the backend.

## Modeling Principle

The model should remain simple, interpretable, and reproducible.

The project gains more value from a clean pipeline and a strong demo than from model complexity.
